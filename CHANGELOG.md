# Changelog

Notable changes to Auroro Wallpapers are recorded here. `v1.0.0`, `v1.1.0` and `v1.2.0` shipped as debug-signed artifacts (the `v1.2.0` GitHub release is explicitly labelled "debug build"); production distribution still requires a configured signing key and verified release APK. `1.3.0` continues from `v1.2.0`.

## [1.3.0] — pending CI verification (debug build)

### Fixed

- **For You no longer stops after the first batch.** The discovery mix previously hard-set `endReached` after one bounded pass — as few as 2 cards when providers were quiet — and `loadMore()` ignored discovery feeds entirely, so the grid silently ended with no spinner, no button and no error. Scrolling near the end now plans a fresh continuation batch (new recipes, already-shown and recently-seen keys excluded), appends only genuinely new validated wallpapers, and keeps the session identity stable so grid scroll position survives batches. Loaded items are preserved when a batch fails; retries are bounded — the feed reports an honest end only after two consecutive batches add nothing new, and Retry starts another batch instead of discarding the mix.
- **"Preview unavailable" tiles eliminated at the source.** Art Institute of Chicago records repeatedly arrived with `0x0` dimensions and non-image categories (every CI discovery run logged AIC `usable=0` and search counts of 0), consumed a bounded discovery request slot per mix, and rendered as broken tiles in Search. AIC is retired: provider, API client, discovery lane, recipe mappings, settings toggle and search/source registration removed; the enum entry remains so previously saved records keep their CC0 attribution and stay readable. Visible grids now contain only Wallhaven (source-reported dimensions) and NASA APOD (view-only, honest unknown dimensions) results.

### Changed

- **Liquid glass on the Kyant0 backdrop engine (replaces Haze).** `io.github.kyant0:backdrop:2.0.1` (Apache-2.0) now renders live glass; the Haze dependencies are removed. Auroro's glue (`core/design/LiquidGlass.kt`) is clean-room: the GPL-3.0 BitChord app was studied for architecture only (page-level opaque recording, glass chrome mounted outside the recorded subtree, saturation → blur → lens stack) and no BitChord code is copied; the Frutiger Aero aqua tint and specular rims are kept. The bottom bar and drawer sheet sample one page-level recording of the NavHost (ambient gradient painted as its opaque base), detail/crop floating controls sample screen-local hero recordings, and pages now scroll behind the floating bar so the glass refracts real artwork. In-content panels keep the lightweight Aero treatment by design (no self-sampling, no per-card captures).
- Glass quality semantics: **Full** = saturation lift + 12 dp blur + API-33 lens refraction; **Balanced** (default) = 6 dp frost + saturation without the refraction shader; **Reduced effects** or **Reduce transparency** = no capture at all with an opaque fallback. Blur requires API 31+, lens API 33+; older devices use the same fallback.
- Performance safeguards around the recording: the upstream engine captures at full resolution and any animation inside the recorded subtree forces a re-capture + re-blur of every glass consumer per frame — a CI run on the software-rendered emulator ANR'd at cold start from the feed spinner alone (run 38427909867). Feed/detail/crop loading indicators are therefore calm static hourglasses (the copy still reports the state honestly), the closed drawer sheet does not sample the page, immersive routes detach the root recording entirely, and the root recording attaches only after the first frame (cold start renders the lightweight fallback chrome immediately; a second ANR on a re-run proved the un-deferred first-frame attach was host-speed-luck on the software renderer).
- Scrollable screens carry their own bottom content padding (content flows behind the floating bar); the retired `art_institute_enabled` preference key is dropped on the next settings write.
- Emulator smoke updated: a new deep-scroll assertion fails if For You ever reaches its end without attempting a continuation (or showing an explicit retry/end state); AIC search assertions were replaced with "retired source must not appear in Search choices"; the Sources screen now asserts the visible retired status card.

### Verification status

- Pending: unit tests, lint, debug/release assembly and the hosted-emulator UI smoke (with cold-start and `gfxinfo` frame metrics) will be recorded here once the CI run for this commit completes. No performance claim is made before those measurements exist.

## [1.2.0] — pending verification and signed release

### Added and changed

- Simplified the Home header: one clear search entry point (the search icon button and the in-field "Search" action were removed as duplicates), no generic subtitle, and no internal counters such as "N catalogues · M validated source searches" in the browsing UI. The static five-topic pill row was removed from Home; the same shortcuts remain available under **Search topics** and inside Search.
- Made the APOD-only empty state archive-accurate: it no longer recommends continuing to "the next provider page" as if APOD were an ordinary paginated keyword search, and explains that **Look further** browses older days of NASA's daily astronomy archive. The generic multi-source empty hint was reworded to describe what loading the next page actually does.
- Replaced the launcher, monochrome and notification glyph with the verified Apache-2.0 Google Material Icons `wallpaper` asset (photo-frame mark), keeping the transparent adaptive foreground and Android 13+ monochrome layer; the previous generic `landscape` glyph and its licence file were removed and provenance records updated.
- Hardened the emulator UI smoke: the post-process-recreation settings assertion now reveals each choice row, polls the real selected state instead of reading a single mid-transition dump, and reports per-label diagnostics (`restored_settings_selection`) in the run report.
- Rebuilt the native Compose presentation across Home, search and filters, image detail/crop, favorites, collections, downloads/history, source status, settings, navigation, and empty/error/loading states while retaining Room-backed user data and the existing download/apply separation.
- Replaced the active source set with Wallhaven, NASA APOD, and Art Institute of Chicago public-domain/Open Access results. Added provider allow-lists, metadata mapping, dimension-aware filters, bounded page caches, and conservative rate pacing.
- Kept NASA APOD records view-only unless an individual reuse permission is independently confirmed; credit/copyright fields are not treated as a licence.
- Disabled Reddit until official OAuth authorization is available. Removed Openverse catalogue requests and its global sensitivity setting/filter; retained legacy saved records and local files without new Openverse network use.
- Rebuilt For You as source-isolated Wallhaven and Art Institute query lanes plus a bounded, newest-first NASA APOD archive lane. Six catalogue recipes have AIC-specific query mappings, one museum query is attempted per mix, and partial provider failures stay isolated.
- Removed recipe/tag evidence as a hard result-rejection gate and removed the forced portrait/1080p For You request. Search-query results now require known source-reported dimensions with a 720 px minimum short edge; APOD dimensions remain unknown and its separate archive lane stays view-only.
- Removed hidden tag/category rejection from discovery quality checks; Wallhaven's source-side `purity=100` policy remains specific to Wallhaven. Reduced Glass/accessibility modes also skip unused Haze backdrop capture.
- Replaced the launcher and notification glyph with the verified Apache-2.0 Google Material Icons `landscape` asset, retaining an adaptive icon background, transparent foreground, and monochrome layer. Added source/licence attribution.
- Moved retired credential cleanup off the main thread and deferred WorkManager lookup until the download repository needs it.
- Separated the basic Follow system / Light / Dark control from Advanced theme. Follow system is the default; fresh installs retain Frutiger Aero as the selected design language to match the supplied glass-forward direction. The system mode resolves light/dark live, and Material 3, Frutiger Aero, and Frutiger Zen each provide both mode palettes. Existing combined appearance preferences migrate safely, while removed legacy preset names no longer appear as design options.
- Rebuilt Settings around source-backed glass cards, compact grouped controls, and theme cards with paired Light/Dark swatches. Retained For You topic preferences under ordinary labels; they guide the curated recipe mix and do not add a global metadata rejection rule. Existing non-botanical choices persist; the retired botanical-style ID reads as ordinary Botanical art and is normalized on the next settings save.
- Renamed the old Frutiger Flower discovery query to ordinary botanical-art language, preserving botanical imagery as content rather than presenting it as a design theme.
- Added Light Aero and Dark Zen Compose Settings previews, mode/theme persistence and palette tests, and a Figma/Penpot-ready nine-screen handoff in [`docs/AURORO_DESIGN_SYSTEM.md`](docs/AURORO_DESIGN_SYSTEM.md). These new changes are not yet verified by CI or on-device visual review.

### Preserved behavior

- Room-backed favorites, collections, history, saved downloads, and legacy metadata are retained.
- Set Wallpaper remains independent of Download: it uses a saved file or disposable cache copy and never creates a download row/file by itself.
- Provider errors, rate limits, unavailable sources, partial results, and empty results are distinct; provider metadata and image dimensions are not fabricated.

### Verification status

CI run [38300321558](https://github.com/Nazatric/Aurora-Wallpapers/actions/runs/38300321558) (Home simplification, APOD empty-state copy, `wallpaper` icon, hardened smoke assertions) was the first run of this rebuild to pass end-to-end: unit tests, lint, debug + release assembly, `apksigner` debug-signature verification, and the complete hosted-emulator UI smoke. CI run [38304599388](https://github.com/Nazatric/Aurora-Wallpapers/actions/runs/38304599388) repeated the full pass and reported **181 smoke checks passed** with measured metrics on the hosted API 35 x86_64 emulator (debug APK variant, live provider network):

- Cold start after fresh install (`am start -W` TotalTime): **4194 ms**; warm restart after process death: **2942 ms**. Hosted-emulator figures, not physical-device results.
- Whole-journey `gfxinfo` frame profile: 527 frames rendered, janky 13.66% (legacy definition 50.85%), frame-time p50 **20 ms**, p90 **34 ms**, p95 **73 ms**, p99 **250 ms**. The journey mixes installs, theme switching, downloads, wallpaper setting, airplane-mode detail loading and settings changes; GPU percentile fields reported by the emulator are not trustworthy and are excluded.
- Post-process-recreation persistence diagnostics (`restored_settings_selection`): Follow system ✓, Frutiger Aero ✓, Aqua ✓ — the earlier "selection did not survive process recreation" failure was a single mid-transition UI-dump assertion, now hardened with scroll-into-view and polled selected state; no app-side persistence defect reproduced.
- Live-provider result counts during that run were low (For You 2 cards, Wallhaven search 2, Art Institute 0, combined 1); the run passed because honest empty/loading states were rendered and no contradictory counts or infinite skeletons appeared. Provider yield varies with live rate limits and is not a UI verdict.

Earlier runs (118→167 checks) failed on stale smoke predicates and script races that were fixed incrementally (`897498e`, `c8a41da`, `d3c8d94`, `74f7ed0`, `61a28e2`, and the hardened selection assertion). Item-level rights review, physical-device performance measurement, and production signing remain open — see [`BLOCKERS.md`](BLOCKERS.md). No FPS claim beyond the emulator figures above, and no published release, is asserted by this changelog.

At the repository owner's direction, `v1.2.0` is published with the CI **debug-signed** APK, explicitly labeled as a debug build in the release name and body, because no computer is currently available to generate a production keystore and the agent token cannot write Actions secrets. This continues the existing `v1.0.0`/`v1.1.0` debug-asset precedent with clearer labeling; a production-signed artifact remains an open blocker and will ship with a later version once `AURORO_KEYSTORE_*` secrets exist.
